# Спецификация задачи matching

## Граница задачи

Дипломная постановка — пакетное назначение на регулярные рейсы. Существующая архитектурная идея `Geo_Matching_and_AI.md` — подобрать водителя к одному on-demand запросу по расстоянию/ETA и score. Не считать это одним алгоритмом. [из заметок: Architecture/Geo_Matching_and_AI.md] [решение студента]

## Сущности

- Пассажирская заявка: повторяющийся маршрут, набор дней, допустимое временное окно и выбранные pickup/dropoff hubs. [из заметок: Business_Department/Product_Logic.md] [решение студента]
- Водитель: доступность на период/рейс, вместимость автомобиля и допустимый коридор. Детальная схема доступности TBD. [решение студента]
- Повторяющийся маршрут, коридор, конкретный рейс и hub-узел. Термины recurring route и коридор есть в продуктовой модели; генератор рейсов в коде не найден аудитом. [из заметок: Business_Department/Product_Logic.md] [из аудита кода]
- Назначение: соответствие заявка → рейс → водитель, с возможностью нескольких пассажиров в пределах вместимости. [гипотеза] [TBD — решить с руководителем]

## Формальная постановка — каркас

Пусть `P` — пассажирские заявки, `R` — экземпляры рейсов, `D` — водители; `x[p,r,d] ∈ {0,1}` означает назначение заявки `p` рейсу `r` с водителем `d`. [рекомендация консультанта]
Лексикографически максимизировать число корректно обслуженных заявок, затем минимизировать число рейсов и после этого суммарное абсолютное временное отклонение; окончательная постановка и трактовка метрик требуют согласования. [рекомендация консультанта] [TBD — решить с руководителем]

Ограничения-кандидаты:

- каждую заявку назначать не более одного раза; [гипотеза]
- временное окно заявки должно пересекаться с временем рейса; величина допуска TBD; [из заметок: Product_Logic] [TBD — решить с руководителем]
- суммарное число пассажиров не превышает вместимость автомобиля; конкретные места/правило TBD; [решение студента] [TBD — решить с руководителем]
- pickup/dropoff соответствуют hub-to-hub модели, без промежуточных остановок в MVP; [из заметок: Business_Department/Product_Logic.md]
- ограничить максимальный detour и расстояние пешего подхода; численные лимиты в дипломной постановке TBD. В существующей продуктовой заметке указано около 100 м пешком до pickup node, это продуктовый ориентир, не утверждённый экспериментальный параметр. [из заметок: Business_Department/Product_Logic.md] [TBD — решить с руководителем]
- водитель не может быть назначен на конфликтующие по времени рейсы; точное правило конфликтов TBD. [гипотеза] [TBD — решить с руководителем]

## Baseline и варианты алгоритма

Baseline: последовательно обрабатывать заявки в фиксированном порядке и назначать ближайший совместимый рейс/водителя; если кандидатов несколько — выбрать меньшую стоимость по расстоянию, затем времени. Порядок обработки и tie-break — параметр эксперимента, предварительно фиксировать до тестов. [решение студента] [рекомендация консультанта]
Основной вариант: TBD между задачей назначения/ILP и эвристикой (например, greedy с локальным улучшением). Выбор после изучения литературы и оценки реализуемости; не выдавать как уже принятое решение. [TBD — решить с руководителем]
`Scaling_Roadmap.md` упоминает Greedy scoring для Phase 1 on-demand matching, но это не выбранный baseline диплома. [из заметок: Architecture/Scaling_Roadmap.md]

## Нетривиальность задачи

В hub-to-hub MVP без промежуточных остановок ограничение detour может выродиться: у водителя нет собственного маршрута, относительно которого естественно считать отклонение. Не следует представлять detour как источник сложности задачи. [рекомендация консультанта] [TBD — решить с руководителем]

Кандидатные источники нетривиальности самой постановки:

- выбор времени отправления рейса внутри временных окон пассажиров, чтобы максимизировать допустимое объединение заявок; [рекомендация консультанта] [TBD — решить с руководителем]
- расписание водителя на несколько коридоров и временных слотов с конфликтами по времени; [рекомендация консультанта] [TBD — решить с руководителем]
- пассажир с несколькими объявленными маршрутами, включая план Multi Corridor; [из заметок: Business_Department/Product_Logic.md] [рекомендация консультанта] [TBD — решить с руководителем]
- отмены и no-show с последующим перепланированием. [рекомендация консультанта] [TBD — решить с руководителем]
